## Milestone 2: Role-Based MCP Server Implementation (`src/mcp/`)
*Objective: Expose ReV as an MCP Server with dedicated tool suites for Admin, Departing Engineer, and New Joiner.*

### 2.1 👑 Admin / Tech Lead Suite
- [ ] **`rev_admin_create_project`**: Create a handover project from local git or GitHub, designating departing person and successor person.
- [ ] **`rev_admin_configure_scope`**: Filter and select relevant data/commits/docs to be handed over, enforcing recipient authorization.
- [ ] **`rev_admin_list_active_projects`**: Retrieve list of active projects with who is leaving and who is joining.
- [ ] **`rev_admin_get_project_roster`**: Get granular departure/joiner details, target roles, and progress for a specific project.

### 2.2 ✎ Departing Teammate Suite
- [ ] **`rev_departing_list_projects`**: List projects from which the engineer is being offboarded/removed.
- [ ] **`rev_departing_get_questions`**: Fetch evidence-backed architectural questions generated by the engine.
- [ ] **`rev_departing_submit_answer`**: Submit explanations and context into the review queue for lead approval.

### 2.3 👤 New Joiner / Successor Suite
- [ ] **`rev_successor_get_project_info`**: Retrieve project overview, target role, and Day-1 onboarding checklist.
- [ ] **`rev_successor_download_artifacts`**: Download approved handover package (`HANDOVER.md`, checklists, citations).
- [ ] **`rev_successor_raise_question`**: Live cited Q&A; if unanswered, automatically escalates a follow-up gap question to the departing person.

### 2.4 Server Plumbing & Client Configs
- [ ] Install `@modelcontextprotocol/sdk` and `zod`.
- [ ] Build stdio entrypoint (`src/mcp/index.ts`) connecting to ReV daemon via `daemon.token`.
- [ ] Generate `.cursor/mcp.json` and `claude_desktop_config.json` configuration templates.
- [ ] Add unit and end-to-end tests (`tests/mcp-server.test.ts`).
